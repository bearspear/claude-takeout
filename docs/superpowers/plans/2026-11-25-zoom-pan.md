# Zoom and pan in the viewer (v1.23.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pictures (gallery, popups, panel and Artifacts images, SVG files) zoom and drag; HTML previews get a zoom bar; the Design canvas zooms and drags.

**Architecture:** Pure maths (steps, clamping, zoom about a point, fit, SVG size and script checks, the page-fit rule, the measuring script) go in `viewer/viewer-logic.js`, unit-tested. Two DOM controllers, `pictureZoom` and `pageZoom`, also live in `viewer-logic.js`, because that file is already inlined into both page templates (`/*LOGIC_JS*/`) and needs no new build plumbing; Node never calls them. The canvas controller lives in `viewer/artifacts-app.js` beside `canvasPage`, its only user. Each app wires the controllers into its existing views.

**Tech Stack:** Plain browser JS (no library), Node's test runner, Playwright-core e2e over `file://`.

**Spec:** `docs/superpowers/specs/2026-11-25-zoom-pan-design.md` (approved 2026-11-25). Read it with this plan; it is the authority.

## Global Constraints

- No change to the page CSPs, `PREVIEW_CSP`, iframe `sandbox` flags, `guardDoc`, `sanitizeHtml`; previews never get `allow-same-origin`. The only change to preview documents is `SIZE_SCRIPT` appended by `previewDoc` and `artifactPreviewDoc`.
- No new library, no new file the templates must inline. CSS: chat viewer in `viewer/viewer-template.html`'s `<style>`; Artifacts screen and canvas in `viewer/artifacts.css`.
- Plain wheel over a picture in the panel, popup or Artifacts page scrolls as today; only the gallery zooms on a plain wheel. Pinch and Ctrl/⌘+wheel zoom (non-passive listener, `preventDefault`).
- Steps (%): 10, 25, 33, 50, 67, 75, 90, 100, 125, 150, 200, 300, 400, 600, 800. Picture range min(Fit, 10%)–800%; page 25%–200%; canvas Fit–200%.
- Drag threshold 4 px: a press that moves more is a drag and suppresses the following click.
- Keys `+`/`=` in, `-` out, `0` Fit, `1` 100%, while the zoom area or its bar has focus (always in the gallery). Gallery Left/Right, Escape, Tab trap and click-outside keep working.
- Bar buttons have `aria-label`s ("Zoom out", "Zoom in", "Fit", "Fit width", "Actual size"); the percentage is an `<output>` with `aria-live="polite"`; the picture area has `tabindex="0"`.
- Light and dark via existing colour tokens; works at phone width.
- `node --check` every edited `.js`; `sh tests/run.sh` green before each commit. Commit as bearspear, message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never stage `.claude/`, `.superpowers/`, `.DS_Store`. No push.

**Plan's own calls (rulings over the spec's letter):**
- Chat-viewer zoom checks go in the new `tests/e2e/zoom.e2e.js`; Artifacts-screen and canvas checks go into `artifacts-viewer.e2e.js`, `combined.e2e.js` and `design.e2e.js`, which already build those fixtures (standalone and hosted). Cost if wrong: moving checks between files.
- Wheel zoom is continuous (`wheelFactor`), buttons and keys use the steps.
- A picture's max zoom is also capped so its longer side stays ≤ 32768 rendered px (`pictureRange`), protecting the browser from a huge SVG at 800%.

## Review Focus

1. A picture whose `<img>` hasn't loaded when the controller attaches (`naturalWidth` 0): it must wait for `load`, then fit; no NaN sizes. → Task 2 test "gallery: picture fits after a slow load".
2. A container of size 0 (panel hidden, phone layout switching): fit must not become 0 or Infinity; it refits when the size appears. → Task 1 unit `fitZoom` invalid cases; Task 3 e2e "panel image: refits after the panel is shown".
3. An SVG with a huge `width` (e.g. `100000`) or `viewBox` → 800% would be a 800 000 px element. → Task 1 unit `pictureRange` cap; Task 3 e2e "huge SVG: + stops at the cap".
4. A drag released outside the window, or the gallery closed mid-drag: no stuck `grabbing` state, next click works. → Task 2 e2e "gallery: pointercancel ends a drag".
5. A page that posts `ct-size` with junk (`Infinity`, strings, negative, from a different frame): ignored, Fit width stays disabled. → Task 1 unit `pageFit`; Task 4 e2e "message from another window is ignored".

- Produces (all exported):
  - `ZOOM_STEPS: number[]` = `[0.1, 0.25, 0.33, 0.5, 0.67, 0.75, 0.9, 1, 1.25, 1.5, 2, 3, 4, 6, 8]`
  - `PICTURE_MAX_SIDE = 32768`
  - `clampZoom(z: number, min: number, max: number) -> number` (non-finite z → 1, then clamped)
  - `stepZoom(z: number, dir: 1|-1, min: number, max: number) -> number` — first step strictly beyond z (epsilon 1e-6) in that direction, clamped; none beyond → the bound.
  - `wheelFactor(deltaY: number, deltaMode: 0|1|2, pinch: boolean) -> number` — `Math.exp(-d * k)`, d = deltaY × (1, 16, 800 by mode) clamped to ±200, k = 0.01 when pinch (ctrlKey) else 0.002.
  - `zoomAbout({ from, to, point: {x, y}, scroll: {left, top}, offsetFrom = {x:0,y:0}, offsetTo = {x:0,y:0} }) -> { left, top }` — keeps the content point under `point`: `c = (scroll + point − offsetFrom) / from`, `new = c × to + offsetTo − point`, each ≥ 0.
  - `fitZoom(natural: {width, height}, box: {width, height}) -> number` — `min(1, bw/nw, bh/nh)`; any non-finite or ≤ 0 → 1.
  - `pictureRange(fit: number, natural: {width, height}) -> { min, max }` — min = min(fit, 0.1); max = max(fit, min(8, PICTURE_MAX_SIDE / max(nw, nh))).
  - `doubleClickZoom(z: number, fit: number) -> number` — at fit (|z−fit| < 1e-6): 1 if 1 > fit + 1e-6 else 2; otherwise fit.
  - `svgNaturalSize(text: string) -> {width, height} | null` — the root `<svg>` tag's `width`/`height` when both are plain numbers or `px`; else `viewBox`'s 3rd/4th numbers when > 0; else null.
  - `svgHasScripts(text: string) -> boolean` — `/<script\b/i` or an `on[a-z]+\s*=` attribute inside a tag (`/<[^>]*\son[a-z]+\s*=/i`).
  - `svgDataUrl(text: string) -> string` — BOM stripped, `data:image/svg+xml;charset=utf-8,` + `encodeURIComponent`.
  - `pageFit(report, containerWidth: number) -> { fit: number, enabled: boolean } | null` — null unless `report.type === 'ct-size'` and `width`, `view`, `containerWidth` are finite and > 0; `width ≤ view + 1` → `{ fit: 1, enabled: false }`; else `{ fit: clampZoom(containerWidth / width, 0.25, 1), enabled: true }`.
  - `SIZE_SCRIPT: string` — one inline `<script>` posting `{ type: 'ct-size', width: documentElement.scrollWidth, view: documentElement.clientWidth }` to `window.top` with target `'*'` on `load` and `resize`, wrapped in try/catch.
  - `previewDoc` and `artifactPreviewDoc` append `SIZE_SCRIPT` after the page's content (after `inlineSiblings(...)` / `inlineArtifact(...)`). `remote` is unchanged.
